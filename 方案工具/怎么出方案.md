# 怎么出方案（从幻游纪 v1 和松石公主 v2 两个真实案例里抽出来的）

> 这是 zhuzong 的核心知识。工具只是把这套做法固化。每出一份新方案，回来修这页。
> 整理：2026-09-06

## 一、流程

```
收需求 ──→ 几轮交流 ──→ 判断规模与责任 ──→ 定价 ──→ 出方案 ──→ Franklin 说「发」──→ 客户选 ──→ 备忘录/协议
 01-需求     02-交流纪要         需求摘要          定价锚      03-方案 JSON → build        ⛔ agent 不发
```

- 需求文档原样存进 `客户/<客户>/01-需求/`，再写一页「需求摘要」：规模数字、底层依赖、和我方方案的对照。
- 交流没录音是常态。每次聊完 3 分钟填 `模板/交流纪要.md`，重点是**他要什么、时间与规模信号、我承诺了什么**。
- 方案存为 JSON，`proposal.py build` 出 Markdown + HTML（浏览器打印成 PDF 发微信）。已发出的版本不改，改就出新版本号。

## 二、定价逻辑（Franklin 实际怎么报的）

1. **按「时间 × 责任等级」收月费，不按功能点计价。** 幻游纪 108 个功能点，方案里一个功能点都没报价，报的是「开发期每月 6,000、维护期每月 3,000」。这避免了逐项议价，也把范围弹性留在自己手里。
2. **两种月份：开发月 6,000 / 维护月 3,000。** 集中开发只占前两个月；之后默认维护月，客户要新功能就把那个月叠加成开发月。客户按需买开发月，我不用一次承诺 3 个月满负荷。
3. **责任等级决定价格，而不是工作量。** 全责档（对稳定性、并发、上线前测试负责，bug 限时修）贵；按需档（只做功能、bug 有空修）便宜。同样的功能，卖的是「谁兜底」。
4. **一次性 + 月费的组合**用于 AI 应用：原型一次性 3,000，之后迭代 1,000/月（松石）。
5. **可变成本一律实报实销、不加价**：AI 算力、接口费。方案里给客户一个预留数（500–1,000/月），避免事后被当成隐藏费用。
6. **甜头放在高档位**：全责档附带「软件成熟后免费做小项目」，按需档「无」。用附加值把客户推向 A，而不是靠降价。
7. **付款前置**：签约付前两个月。三个月开发期只剩一次收款风险。

数字锚见 `定价锚与条款库.json`。

## 三、方案结构

### 两选项对照（幻游纪式，适合开发类项目）

| 维度 | 写什么 |
|---|---|
| 适合 | 一句话画出两种客户，让他对号入座 |
| 交付目标 | 用「多少用户能稳定用」定义完成，而不是功能清单 |
| 时间节点 | 有硬节点（国庆）就写；按需档写「不承诺固定日期」 |
| 合作期 | 全责 6 个月（3 开发 + 3 维护）；按需 3 个月一签 |
| 费用 | 月费 × 期数 = 合计；付款节奏 |
| 责任范围 | ⭐ 两档最大的差别就在这里，写清楚兜底什么、不兜什么 |
| 附加 | 全责档的甜头 |

后面三段：**共同前提**（第三方费用、资质、配额都是客户的）、**怎么选**（替他做决定的话术 + B→A 转换条款）、**费用相关说明**（预防扯皮：配额不足不算故障、免费项目的边界、已经垫付的测试费）。

### 单选项清单（松石式，适合服务类）

服务项逐条列，每项独立勾选、独立计费；月费项 + 一次性项 + 实报实销项分开合计；共同前提写素材、修改轮次、48 小时视为认可、不承诺效果。

## 四、发出前的检查清单

- [ ] **范围边界写了没？** 承诺「对整体质量负责」的同时，必须写「做哪些 / 不做哪些」。幻游纪 v1 缺这一条（见 `客户/幻游纪/01-需求/需求摘要.md`）。
- [ ] **有没有留空的数字？** 幻游纪 v1 方案 B 月费是空的。build 会把 `单价: null` 标成「待定」，台账里能看到。
- [ ] **前提里第三方费用、资质、配额、版权是不是都推给客户了？**
- [ ] **不承诺效果**：流量、涨粉、成交、性能（按需档）。
- [ ] **时间节点和人力对得上吗？** 半个月出试用版，范围就得砍到核心链路。
- [ ] **付款节奏写了吗？**
- [ ] ⛔ **Franklin 亲口说「发」才发。**
